# ADR-0006：界面语言跟随浏览器，剪藏文件里的固定文字按保存时的语言写

- **状态**：已采纳
- **日期**：2026-10-07（ALAG-7，用户决定 1、2；实现结构由编排者定）

## 决策

**界面语言**：跟随浏览器。浏览器语言是中文（简体或繁体）时显示简体中文，其余语言一律英文。设置页不提供语言选项。

- 文案放在 Chrome 的 `public/_locales/{en,zh_CN,zh_TW}/messages.json`，`default_locale` 为 `en`。`zh_TW` 与 `zh_CN` 内容逐字相同，由测试保证。Chrome 的 `_locales` 不接受不带地区的 `zh`，所以繁体只能靠这份副本；未单独提供 `zh_HK`。2026-10-08 在 UTM macOS 26.6.2 / Chrome 155.0.8059.40 上设置 `AppleLanguages = (zh-HK)` 并完整退出重开后，`chrome.i18n.getUILanguage()` 实际返回 `zh-TW`，扩展面板和设置页显示简体中文；因此不能笼统认定香港中文回落英文。其他系统和版本按实测确认，见 [复测记录](../research/ALAG-8-vm-retest.md)。
- 运行时只通过 `src/shared/i18n.ts` 的 `t()`/`tn()` 取文案，底下是 `browser.i18n.getMessage`。要按语言分支的地方（日期格式、单复数、`<html lang>`）只看 messages.json 里的 `uiLang` 键，不看 `getUILanguage()`，这样分支与 Chrome 实际选中的那份文案一致。
- console 日志和代码注释不翻译。

**剪藏文件里的固定文字**（`[原文]`、`# 摘录 - `、`[跳回原文]`、`未命名剪藏`、平台名、媒体类别名等）：按**保存时**的界面语言写。frontmatter 的键本来就是英文，不变。

**读文件时不依赖这些文字**：摘录条目按时间行的形状识别（`时间 · [任意文字](链接)`），不看链接文字；摘录文件按 `quote:<地址>` 记录定位，不按文件名。所以换浏览器语言后，旧文件能继续追加、改批注；同一个摘录文件里可能出现两种语言的链接文字。

## 理由

- 扩展面向所有用户（ADR-0005），只有中文会把不读中文的人挡在外面。跟随浏览器是浏览器扩展的通行做法，省掉一个设置项。
- 剪藏文件是给用户自己读的，固定文字用他当时的语言最自然。文件格式靠 frontmatter 和形状识别，不靠文字，所以混用不会坏。

## 考虑过的方案

- **设置页加语言选项**：多一项存储和状态，绝大多数用户不会去改。
- **文件里的固定文字一律英文**：中文用户的笔记里会出现英文标签。
- **运行时自己读 JSON、按 `getUILanguage()` 选语言**：繁体中文和测试切换都更好控制，但 manifest 字段只能靠 Chrome 的 `_locales` 解析，两套选择规则可能不一致；用 `uiLang` 键可以让两边一致。
