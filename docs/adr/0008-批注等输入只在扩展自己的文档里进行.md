# ADR-0008：批注等用户输入只在扩展自己的文档里进行

- **状态**：已采纳
- **日期**：2026-10-08（ALAG-16，安全审计 S1，用户决定）

## 决策

扩展注入到网页里的界面（页面右下角提示）**不放任何输入控件**。需要用户输入的操作（批注、标题、标签）一律在扩展自己的文档里完成：工具栏面板、选项页。页面提示上的「加批注…」只负责打开面板并让面板进入该剪藏的编辑态。

## 理由

- closed shadow root 只隐藏 DOM 节点，不清除跨越 shadow 边界的键盘与输入事件携带的内容。网页脚本在 window 上注册捕获监听器就能从 `keydown.key`、`beforeinput.data`、`input.data` 重建用户输入的全文，页面上的第三方脚本处在同一位置。审计用真实组件和真实 Chrome 键盘事件复现过。
- 在页内加 `stopPropagation` 无效：页面的捕获监听器先于扩展的监听器执行。
- 扩展源 iframe 可以把输入留在页面里，但要开放 `web_accessible_resources`（暴露扩展 id、允许页面嵌入），本阶段不值。
- 面板已有「关闭即写入」机制（每次输入同步到 service worker，关闭时落盘），把输入搬进面板不丢内容。

## 后果

- 页面提示不再有展开的批注框；toast 专用的 `toast-note` Port 下线。
- 面板多一个「打开即编辑指定剪藏」的入口：service worker 在 `storage.session` 记下 tab → 剪藏 id，面板 `start` 时优先消费。
- `chrome.action.openPopup()` 只能在活动窗口打开，失败时页面提示保留并说明怎么办。
- 面板打开后按当前活动标签页发 `start`。service worker 在调用 `openPopup` 前核对发起提示的标签页仍是该窗口的活动标签页，不是就不打开、页面提示按失败处理；核对之后到 `openPopup` 之间的极短时间内切换标签页，面板会对新标签页走「打开即保存」，这是已知残余。
- 以后任何注入网页的界面新增输入控件都违反本决策。

## 考虑过的方案

- **保留页内输入框，加 stopPropagation**：无效，见理由。
- **扩展源 iframe**：有效但要开放 web_accessible_resources，推迟。
- **side panel**：需要 user gesture，经消息转发后是否保留不确定，且是另一套 UI。
