# ADR-0003：X 内容只解析当前页面的 DOM，不调用 API

- **状态**：已采纳
- **日期**：2026-10-06

## 决策

保存 X 的单帖、作者串、长文和引用帖时，只解析用户当前打开的页面 DOM，使用用户本人的登录态，不调用 X 的官方 API 或逆向接口。作者串没有加载全时，只在用户点了保存之后才自动滚动或点击展开，上限 50 条或 15 秒；超过上限就存下已加载的部分，抽取状态记为"部分"。

## 理由

这样做账号风险和用户自己手动浏览一样。不需要 API 密钥，不产生费用，也不依赖 X 开放平台的政策。代价是 X 改版时要跟着维护选择器，这部分由各站点的 HTML 样本测试兜底。

## 考虑过的方案

- **X 官方 API**：要付费分级，有调用配额，还要用户另外授权。只给自己用的工具承担不起。
- **逆向接口**（例如 x-to-markdown 类工具的做法）：内容更完整，但有封号风险，而且违反服务条款。

## 修订：链接目标从页面内存里补（2026-10-07，ALAG-3）

- **状态**：已采纳（用户在 ALAG-3 设计期选定）

M2 采样时查实，有两样东西 DOM 里没有：
1. 被引用帖的原帖 URL。引用框是 `div[role=link]`，样本 `tests/fixtures/x/quote-marcelkargul.html` 里被引用帖的 id 出现 0 次。
2. 链接卡片的真实 URL。卡片只有 `t.co` 地址和域名。

这两样只在页面主世界 React fiber 的帖子对象里有：`quoted_status_permalink`、`entities.urls[].expanded_url`。数据已经在页面内存里，读取时不发任何请求。

决定：
- 正文、图片、视频封面、作者串边界都照旧只解析 DOM。
- 只用 `scripting.executeScript({world:'MAIN'})` 装一个监听器。收到同步事件后，它把每个 article 的 `{id, 原帖 URL, t.co 映射, 视频时长}` 写成 `data-alayo-x` 属性，采集脚本仍然只读 DOM。
- 读不到时照常保存：引用头不带「原帖」链接，卡片保留 t.co，时长从 DOM 角标读，读不到就不写。

理由不变：不调用 API，不发额外请求，账号风险和手动浏览一样。代价是多依赖一处 X 的内部结构（fiber 上 `memoizedProps.tweet`），这一段只能在真实页面上验证。其余逻辑由带 `data-alayo-x` 属性的 HTML 样本测试兜底。

长帖在列表里的"显示更多"全文，DOM 和 fiber 都没有。这种情况存截断文本并附原帖链接，抽取状态记为"部分"。
