# ADR-0010：Get 扩展为采集＋阅读标注，阅读器只打开剪藏库里的书

- **状态**：已采纳
- **日期**：2026-10-17（ALAG-23，用户决定）

## 决策

Get 不再只是采集端。它增加一个扩展自有的**阅读器**页面，用来阅读和标注剪藏库里的 PDF、EPUB（统称书），并在阅读器里提供翻译。

边界：
- 阅读器只打开剪藏库里的书，不打开库外的本地文件。网上的 PDF 先按现有流程存成媒体剪藏，再在阅读器里打开。
- 阅读器有书架，列出剪藏库里的全部书。入口：工具栏面板、保存 PDF 后的页面提示、选项页。
- 标注写回书文件本身，另外生成一份读书笔记剪藏（见 ADR-0012）。

## 理由

- Chrome 不允许往内置 PDF 查看器里注入脚本（ADR-0004 后果），浏览器也打不开 EPUB。要在书上选字标注，只能用扩展自己的页面渲染。
- ADR-0008 规定输入控件只能放在扩展自己的文档里。阅读器正好是扩展自己的文档，批注输入放在这里不违反它。
- 面向通用用户（ADR-0005）。Workbench 只有 Mac 版，Notes 还接不进来，把阅读标注放进它们会让大部分用户用不上。
- 只碰剪藏库里的文件，与「剪藏库是 Get 唯一的写入目标」（ADR-0001）一致，不必为库外文件逐个申请写权限。

## 考虑过的方案

- **阅读与标注放到 Workbench / Notes，Get 只负责存文件**：符合家族分工，但非 Mac 用户和不用 Workbench 的用户就没有这个功能。
- **允许打开库外任意本地文件**：要对每个文件单独授权写入，Get 的写入范围也不再只是剪藏库。以后有需要再议。

## 后果

- 扩展体积会明显增大（pdf.js、foliate-js 及其 worker）。
- README 里「媒体剪藏原样不改」的说法要改准确。标注过的书，元数据侧档记 `annotated: true`。
- 阅读器里的输入（批注）不受 ADR-0008 的限制。页面提示仍然不放输入控件。
