# ADR-0005：面向通用用户，Workbench 为可选对接

- **状态**：已采纳
- **日期**：2026-10-07（ALAG-6，用户决定）
- **修订**：[ADR-0001](./0001-只写文件系统-第一阶段只对接workbench.md) 中“第一阶段只对接 Workbench”的产品定位。ADR-0001 的“只写文件系统、不调 API”不变。

## 决策

Alayo Get 面向所有用户，不只服务 Alayo Workbench 的用户。扩展的界面、首次设置和 manifest 不再以 Workbench 为默认前提：

- 首次设置只有两步：选剪藏库文件夹；说明重启浏览器后还要授权一次。
- Workbench 的接入说明放进“配合 Alayo Workbench 使用（可选）”小节，默认收起，首次设置页和设置页都有。
- 除这个小节外，界面文案不提 Workbench。

## 不变的部分

下面这些最初是为 Workbench 定的（ADR-0001、ADR-0002），但对任何用户都无害，保持不变，剪藏文件的格式也不变：

- 附件和元数据侧档放在点开头的隐藏目录里，一篇剪藏只对应一个可见文件。
- 文件名去掉开头的点。
- 重复保存时不覆盖原文件。

## 理由

存下来的是普通的 Markdown 文件和媒体文件，任何编辑器、笔记工具或文件管理器都能直接用，本来就不依赖 Workbench。把 Workbench 写成必经步骤，会让不用它的人以为装了也用不了。Workbench 用户的接入方式没变，只是挪进了可选小节。

## 考虑过的方案

- **完全删掉 Workbench 说明**：Workbench 用户就得自己摸索怎么把剪藏库加为监控目录。
- **在设置里加“我在用 Workbench”开关，打开后才显示说明**：多一项存储和状态逻辑，收益和默认收起的小节一样。
