# ADR-0012：标注写回书文件本身，读书笔记剪藏由标注单向生成

- **状态**：已采纳（以 ALAG-30 实测通过为前提）
- **日期**：2026-10-17（ALAG-23，用户决定）

## 决策

**书文件是标注的唯一真源。**

- **PDF**：用标准注释写回原文件。高亮写成 `/Highlight`（带 QuadPoints），批注写进 `/Contents`（配 `/Popup`）。用 pdf.js 的增量保存，原文件字节不动，只在末尾追加。
- **EPUB**：按 W3C EPUB Annotations 草案（2026-10-15 Working Draft）写入包内的 `META-INF/annotations.json`，位置用 EPUB CFI 表示。草案定稿后迁移到正式格式。重新打包时 `mimetype` 必须是第一个条目且不压缩。先写临时文件，再整体替换。
- **读书笔记剪藏**：每本有标注的书同时生成一份 `笔记 - 书名.md`。它是剪藏：`medium: notes`，出处沿用书的出处。标注一变就整份重写。文件头写明由 Get 生成，要改请在阅读器里改。每条标注写原文摘句和批注，再加位置：PDF 写页码和 `书名.pdf#page=N` 链接，EPUB 写章节和 CFI。
- **保存时机**：停顿几秒后自动保存，关闭阅读页时再存一次。写之前核对文件修改时间，如果打开以后被别的软件改过，就不覆盖，提示用户重新载入。

## 理由

- 「存下的文件不依赖 Alayo 产品也能用」（ADR-0005）。PDF 的标准注释在 Preview、Acrobat 等阅读器里都能看到。增量保存不碰原有字节，对签名文件和加密文件都更安全（pdf.js 源码已核实，加密文件保存后仍然加密）。
- EPUB 没有通用的内嵌注释标准。W3C 草案是唯一在标准化轨道上的格式，Thorium 已有按它导入导出的代码。其他阅读器大多看不到这些标注，所以另生成一份 Markdown 读书笔记兜底，任何编辑器和 Workbench 都能读。
- 读书笔记只单向生成。双向同步要处理冲突合并，代价远大于在 .md 里直接改批注带来的方便。

## 考虑过的方案

- **标注只存进侧档或读书笔记，不碰书文件**：最安全，但换个阅读器就看不到标注，也违背用户「存入同一文件」的要求。
- **第一次标注时另存一个带标注的副本**：原件不动，但剪藏库里会有两份同一本书，按媒体地址查重和 Workbench 的卡片都会乱。
- **EPUB 仿 Calibre 的内嵌格式**：Calibre 用户能直接看到，但格式没有公开规范（Calibre 只在 5.0 更新说明里提到「存在书文件里」），需要逆向分析。

## 后果

- README 里「媒体剪藏原样不改」的说法要改。PDF 是原字节不动、末尾追加；EPUB 是内容不变、字节变了。
- W3C 草案的字段还会变（JSON Schema 仍是 T.B.D.），以后要迁移。
- 书被移动、改名或删除时，读书笔记剪藏要有对应处理（ALAG-34）。
- Preview 是否显示高亮上的批注文字、epubcheck 能否通过，都以 ALAG-30 的实测为准。
